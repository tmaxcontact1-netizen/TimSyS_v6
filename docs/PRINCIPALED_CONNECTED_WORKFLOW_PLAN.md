# Connected Principal’Ed workflows

10 October 2026. Implements the platform-wide benchmark rather than making every module a task board.

## Working conventions

Start with a person, event, class, date or question. Keep record context visible while moving to related work. Select records by name; internal identifiers remain backend contracts. A return link opens the originating record. Specialist screens retain their own appropriate calendar, register, profile, marking or network layout. Administration stays separate from routine work.

Use explicit save, submit, approve, send and close actions. Viewing, selecting and navigation cannot approve or activate records. Empty pages provide a real starting action; no demo records are inserted. Errors preserve inputs. Destructive actions retain confirmation and backend dependency checks.

## Implementation sequence and acceptance

1. Correct event references to the documented event-code contract. A task created from an event must contribute to that event’s readiness report.
2. Carry event context through planning, invitations, attendance, logistics, safety, finance, tasks, decisions, messages and document linking. Keep a visible return path; do not imply global lists are filtered when they are not.
3. Replace technical person and subject inputs with named selection wherever a real directory exists. Preserve unsupported existing reference types explicitly instead of reinterpreting them.
4. Present the home and workspace entry points as recognisable jobs, with plain-language guidance. Preserve specialised workspaces, permission checks and governance.
5. Verify full linked journeys with a new isolated database, plus existing usability, scrolling and governance regressions. Package only reviewed source changes, preserve other applications’ published bundles, verify release digests and update availability.
