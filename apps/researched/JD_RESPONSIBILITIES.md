# Roles and responsibilities — Research’Ed 0.10.0

## Scope and methodology

A deterministic, separate JD tool; no AI, MCF instrument change, semantic classification, automatic role equivalence or inferred handoff. Upload DOCX, text-layer PDF, TXT or a ZIP of supported files. Each document retains its original bytes and SHA-256, extracted text, passage IDs and offsets, page/paragraph location, original dimensions and extraction warnings. Responsibility bullets remain intact where text-layer structure identifies them; unknown structure is available for researcher checking. PDF reading order is not guaranteed and no OCR/repair is silently applied.

The parser uses versioned structural rules (jd-literal-structure.v1). It detects common JD field labels, Standard/Domain headings and named section headings. It is not a universal layout recogniser. Researchers can classify a passage as statement/other text or recognise an original heading using its exact source wording and reassign it only to a dimension already present in that document; immutable extracted text and original dimension remain retained. Role-title corrections are separate from source text. Exclusions are reversible. Confirmation is required before exports.

The role column identifies the source JD owner, not an inferred grammatical actor; passages may explicitly describe other roles. The matrix preserves the original dimensions instead of creating a new thematic framework. Editable literal search terms are retrieval aids. The special-education preset retrieves AEA, CST, intervention, referral, accommodation and parent-related passages; it is not a relevance classifier or complete decision procedure. All matches remain visible regardless of whether a connection is documented.

Reporting chains use only explicit Reporting To fields, with whitespace/case-insensitive exact title joins between uniquely named supplied JDs. Principal and Section Principal are not silently merged. Unmatched counterpart wording, duplicate title ambiguity and cycles are exposed. Collaboration and professional guidance retain their own labels. These reporting chains do not establish intervention sequence or approval authority. Operational relationship phrases retain complete evidence rather than guessing actor/target. Two passages can be compared without inventing a handoff. Missing connections remain unresolved, with later duties still shown; the tool does not generate a normative missing-link list from unstated expectations.

## Workflow

From Research’Ed home select Roles and responsibilities (opens within Research’Ed; background analysis continues). New collection → upload ZIP/documents → Check extraction. Select each source, inspect original headings/text and download the original where needed. Save optional checks, or Confirm extraction and explore. Choose the special-education retrieval preset or enter semicolon-separated terms. Use Responsibility matrix and Relationships and gaps; inspect exact reporting chains and compare passages. Download JSON, HTML and CSV together. CSV neutralises spreadsheet formula prefixes without changing retained source text. JSON includes all source text, provenance, review decisions, revision history and the selected retrieval terms; originals remain separately downloadable.

Edit extraction, Undo and Redo are explicit. Permanent source deletion removes its original and extracted content, clears undo/redo snapshots to prevent resurrection, and invalidates confirmation. Collection deletion removes the complete folder. Deletion is confirmed and intentionally cannot be undone.

## Isolation and persistence

The new /api/jd routes use a dedicated jd-responsibilities folder beneath Research’Ed storageRoot. Each collection has UUID paths, original binary files and an atomically replaced project.json with revision checks and review history. Serialized requests prevent competing updates. No SQL schema/migration, database access, AI call, MCF queue or shared runtime change is introduced by the tool. Source-size/expanded-archive limits, supported-format checks and same-origin mutation checks apply. Test storage is disposable and separate from the live app. Publication does not install the update or restart processing.

## Acceptance evidence

The supplied nine-JD ZIP is exercised only in local ignored verification artifacts; source documents are not committed or included in the update. Tests verify original-byte hashes and every passage offset, distinct role titles, original dimensions, AEA parent-contact/enrolment/referral passages, AEA Teacher → AEA Coordinator → Head of Schools, and no Principal/Section Principal identity inference. Browser/API checks cover confirmation, comparisons, all three exports, undo/redo, stale revisions, cross-origin rejection and physical deletion. Existing workflow and semantic regression suites also run with disposable databases. A rejecting database stub confirms JD operations make no database calls (the existing host has a separate startup recovery call).

## Extraction v2: documentary levels and physical provenance

New imports record `extractionRules: jd-literal-structure.v2` per document. Existing saved imports are not rewritten. PDF physical lines retain text, raw-extraction offsets, page coordinates, font identifiers and PDF text-item indices. Documentary units have `sourceSpans` referring to all contributing physical lines; their existing start/end offsets still address the canonical `extracted` text exactly. Reconstruction changes whitespace between lines only; it does not repair words, dehyphenate, split compound bullets or infer missing text.

PDF continuation requires compatible indentation and line spacing (within 1.48 times the line height), or an unfinished, geometrically compatible page continuation. Bullets, fields and headings end the previous unit. Headings use literal labels and document-local heading typography. Page furniture stays outside continued units. A detached list separated by a large gap and indentation change cannot inherit the previous heading: its heading remains unassigned with a review warning. Explicit degree/experience wording can identify a qualification block without manufacturing the missing heading. Programme-delivery table fragments retain unresolved cell associations as metadata. Approval/signature regions remain separate from duties.

The six levels are `heading`, `descriptor`, `statement` (responsibility/bullet), `metadata`, `qualification`, and `approval`. Descriptor/summary prose remains searchable in the matrix with a distinct documentary-level label; it is not counted as a responsibility. DOCX paragraphs and numbering remain authoritative. Qualification and approval material remains available in extraction review and JSON, outside responsibility rows.

`review.roleEquivalences` is an optional model/API-only list of explicit researcher declarations: `{id, left, right, reason, recordedAt, origin: "researcher"}`. Submit a UUID and rationale through the existing review endpoint; the server stamps a new declaration's time and validates both titles. Subsequent changes require a new ID. Decision snapshots remain in history, including through undo/redo. No alias UI or automatic application is added: these declarations do not change source titles, exact-title reporting chains, or relationship inference.

Verification: `node scripts/verify-jd-extraction.mjs` uses `JD_FIXTURE_ZIP` and the pre-change extraction snapshot at `verification-local/jd-extraction-v2/before.json`; it checks every physical span, unchanged original hashes and DOCX paragraph structure, and writes before/after counts plus unresolved cases. The snapshot and original JDs are private test artifacts, not repository fixtures. `tests/jd-extraction.test.ts` supplies portable synthetic geometry/DOCX adversarial cases.

## Literal passage relationships (Test 2 refinement)

The relationship layer now distinguishes `documentedRelationships`, `mentions`, `documentaryBoundaries` and `unresolvedConnections`; existing metadata `relationships` and `reportingChains` remain separate. A closed grammar recognises literal relational verbs and prepositions, explicit noun-phrase actors, documentary imperative subjects, and coordinated predicates. Multiple counterparts receive separate records sharing their evidence. Exact source title spellings, including plural and abbreviated forms, remain distinct. No matching responsibility in the counterpart's JD is fabricated, and no relationship creates a process sequence.

Each passage relationship retains the source JD role separately from the grammatical actor, the actor-resolution basis, literal phrase and counterpart wording with exact spans, source sentence and full passage, document/location/physical spans, stated object and purpose/conditions. Semicolon clauses are examined separately for negation while the entire sentence remains in evidence. Source wording such as `share with` remains literal; its explicitly stated object `outcomes` is stored separately rather than synthesising a new quote. Negative clauses are preserved as documentary boundaries, not positive assignments.

The grammar deliberately leaves unclear actors/pronouns unresolved. Eligibility-dependent provision and anonymous committee participation receive passage-grounded gap records: no decision-maker or committee membership is supplied. These flags do not assert that an exhaustive semantic search has proved absence elsewhere in the corpus; any cross-document resolution requires documentary review. Researcher equivalence declarations remain unchanged and are not applied automatically.

The wider bullet continuation rule requires a hanging continuation, the same font and page, a lowercase continuation, an unfinished `and`/`or`, and a gap no greater than 1.85 line heights. Existing heading, field, bullet, approval and footer boundaries take precedence.

Verification uses `tests/jd-documentary-relationships.test.ts`, the existing JD and extraction tests, `scripts/verify-jd-relationships.mjs` (private pre-change snapshot in `verification-local/jd-relations-v1/before.json`), and browser-generated JSON/HTML/CSV with typed observations and source evidence. No live import is rewritten.
